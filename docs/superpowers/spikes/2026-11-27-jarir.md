# Spike: jarir.search (jarir.com Saudi, English, SAR) - 2026-11-27

Status: PASS (Step 2 gate met). Op `jarir.search`, AA site `jarir`, minTier 1.

## Data source
jarir.com/sa-en search is client-rendered from a **Constructor.io** search API (public site key,
embedded in the page JS). The op calls it directly (not jarir.com, so no Cloudflare/PerimeterX):
`GET https://ac.cnstrc.com/v1/search/{q}?key=key_KcSYfmQTEwRpBnd9&num_results_per_page=40&c=cio-fe-web-jarir&page={page}&sort_by={sort_by}&sort_order={sort_order}`
Page loaded for capture: `https://www.jarir.com/sa-en/catalogsearch/result?search=laptop`.
Direct jarir.com `/api/catalogv2/...` and `/api/v2/...` calls return 403 (Cloudflare) - not used.

## Recipe (spec: api-specs/jarir.json)
- params: `q` (required), `page` (optional, default 1, 1-based), `sort_by` (relevance|final_price, default relevance), `sort_order` (ascending|descending, default descending).
- `--extract response.results`
- `--pick`:
  - `id=data.id`, `title=value`, `brand=data.metadata.brand`, `image=data.image_url`, `path=data.url`
  - `price=data.metadata.additionalDataToReturn~GTM_final_price\W+([0-9.]+)` (the SALE price; regex into a JSON-string field)
  - `origPrice=data.price` (list price, number; equals price when no discount)
  - `saving=data.metadata.additionalDataToReturn~GTM_product_save\W+([0-9.]+)` (SAR amount off; absent when no discount)
- Learned from capture `--from <cap> --pick-request <id>` with one example (a 2nd browser capture hit a Cloudflare challenge). The spec was then hand-edited: literal public key in URL (AA had turned it into a session ref), `page`/`sort_*` slots + params added, `public` removed.

## Field mapping to Product
id=id; title=title; price=Number(price) (string in output!); currency="SAR" (constant, not in data); origPrice=origPrice (number; treat origPrice==price as no discount); discountPct=round(saving/origPrice*100) or (1-price/origPrice); rating, reviews: NOT exposed (null); image=image (absolute); brand extra.
**URL rule:** `https://www.jarir.com/sa-en/` + `path` (e.g. `samsung-m1e-smart-tv-682538.html`). Path is relative in data; id embedded as suffix. (Product page itself not fetched - Cloudflare; pattern follows the site's own `/sa-en/` links and the Constructor `url` field.)
Note: `id` is numeric SKU for all 320 checked items except a few non-numeric ids (e.g. `JPP-8906062165287`) seen on samsung tv page 2 - treat as opaque string.

## Saudi store verification
- Page `og:title`: "laptop | Saudi Arabia | Jarir Bookstore"; canonical `/sa-en/`; the site's own API calls use store `sa-en` / `sa_en`, `country=sa`; filter file `meta_filter_sa_en.json`.
- Constructor client `c=cio-fe-web-jarir`; the index has no store param. Whether Kuwait/Qatar use another index is NOT verified (not tested; their storefronts not hit).
- SAR: not printed in any payload we could read (prices are bare numbers; live price API is 403). Prices are plausible SAR (MacBook Pro 14" 9499, Samsung 55" 4K TV 1999). Concern: currency is inferred, not proven.
- Product URLs: `/sa-en/{path}`.

Sort: `sort_by=final_price&sort_order=ascending` works (laptop: 5, 19, 19, 19, 25 - accessories first). `sort_by=price` sorts list price instead; use `final_price`. Empty sort values -> HTTP 400, hence defaults in URL.

## Bait pricing / options
No option-style pricing: each item is one SKU with one sale price. Discounts are real list-vs-sale (36/40 items in fixture discounted, up to ~50%). Search results are accessories-heavy (relevance returns cases/covers; e.g. "iphone 16" page 2 starts with a case) -> app accessory filter needed.

## Caveats
- `price` is a string, `origPrice` a number, `saving` a string with decimals.
- Prices come from the Constructor index (GTM_final_price), not the live catalogv2 API the page overlays; may lag live price (unverified, same SKUs).
- Constructor key is the site's public key; could rotate.
- ~3 page loads (browser capture) hit jarir.com; third attempt got a Cloudflare challenge. Calls themselves touch only ac.cnstrc.com.
- `page` beyond last returns fewer/empty items; total in `response.total_num_results` is not exposed by the pick.
