# Spike: shein-sa.search (SHEIN Saudi, ar.shein.com, SAR) - 2026-11-27

Status: PASS WITH CAVEATS (Chrome-only, tier 3). api-anything is blocked, so there is no AA spec.
Prototype: `scripts/shein-sa-search.prototype.mjs`. Fixture: `tests/fixtures/shein-sa-search.json`
(real `sheinSearch("wireless earbuds", 1)` result, 120 items).

## Saudi storefront and language
- There is no English KSA storefront. `sa.shein.com` does not exist (NXDOMAIN). `ar.shein.com` is the
  `hreflang="ar-sa"` site (`SiteUID":"ar"`, `currency":"SAR"`, prices `SR18.40`).
- The site has no English option: `bff-api/user/language/list` returns `{"language_list":[]}` and
  `SUPPORT_LANGS` is `[]`. The English hreflang sites (www/us/de...) are other countries, so they are not used.
- `goods_name` is Arabic. Each item also has `goods_url_name`, an English URL slug, for example
  `Lenovo-EA166-Bluetooth-Earbuds-HD-Sound-Quality-...`. The prototype makes `title` from the slug
  (hyphens become spaces) and keeps `titleAr`. All 958 items checked had ASCII (English) slugs.
  The slug loses some punctuation (for example "6.2L" becomes "6 2L").

## Data source
- Search URL: `https://ar.shein.com/pdsearch/{q}/` (page 2+: `?page={n}`).
- Page 1: the server renders only about 20 items. The page JS then calls
  `GET /bff-api/product/get_products_by_keywords?_ver=1.1.8&_lang=ar&cate_type=4&keywords={q}&channelId=8&page=1&limit=120&...`
  (signed headers). The prototype reads that response with `page.waitForResponse`. It gives 120 items.
- Page 2 and later: no XHR. The server renders about 119 items into `var gbRawData`
  (`results.bffProductsInfo.products`, total in `.num`). The prototype reads `window.gbRawData`.
- Both sources use the same product object.

## Field mapping
- `id` = `goods_id` (string). `url` = `https://ar.shein.com/{goods_url_name}-p-{goods_id}.html`. This is the
  same pattern as the links in the page HTML.
- `title` = `goods_url_name` with hyphens as spaces (English). `titleAr` = `goods_name`.
- `price` = `salePrice.amount` (SAR string, for example "18.40"). `currency` = SAR: `amountWithSymbol` starts
  with `SR`. Also `usdAmount` exists.
- `origPrice` = `retailPrice.amount` when it is greater than the price. `discount` = `unit_discount`
  (percent; the same as `retailDiscountPercent`). `discountPrice.amount` is the SAR amount off, not a price.
- `rating` = `comment_rank_average`. `reviews` = `comment_num` (capped; `comment_num_show` is "1000+").
- `image` = `https:` + `goods_img` (405x552 thumbnail).
- Extra fields: `promotionInfo` (flash or promo end time), `isInversion`, `srpDiscount`, `coupon_prices`, `stock`, `soldOutStatus`.

## Verification (one warm session, 4 s gaps)
| query | p1 items / ms | p2 items / ms | p2 ids also on p1 |
|---|---|---|---|
| wireless earbuds | 120 / 3757 | 119 / 4108 | 30 |
| air fryer | 120 / 5296 | 119 / 11109 | 14 |
| phone case | 120 / 7937 | 119 / 3574 | 17 |
| power bank | 120 / 4424 | 119 / 3434 | 12 |
All items had an English slug title, SAR prices and `https://ar.shein.com/...-p-<id>.html` URLs. Page 2 is mostly
different, but 10-25% of its ids repeat page 1 items. The ranking is personal or shuffled between loads (p1 and p2
were loaded in different sessions), so dedupe by `id`. `num` totals change between loads (8499 / 8531).

## Sort
`sort` URL param (`sort=10` price low to high, `11` high to low, `7` top rated, `9` new) is the usual SHEIN list
param, but it is NOT verified. `power bank` p1 `&sort=10` gave the same order as relevance: the page-1 XHR has no
sort param. The p2 `&sort=10` load hit the risk challenge. Sort client-side for now.

## Bait pricing and discounts
- Discounts are steep and often inflated: on "wireless earbuds" p1, 111 of 120 items are discounted, median 45%
  and max 96% off `retailPrice`. Other queries have a median of 4-8% and maxima of 30-82%.
- `salePrice` can be a promo or flash price (`promotionInfo` with `endTime`, for example "valid until 11-28 23:59").
  It can also be a new-user price: `isInversion: "1"` is on all items, but its meaning is not confirmed. Treat
  `origPrice` as SHEIN's claim.
- The listing has no per-option "from" pricing. Each card is one SKC (one color). Sizes share the price.
- Results mix in accessories (cases on "power bank"), so an accessory filter is needed.

## Caveats
- Tier 3 only: it needs a real Chrome window (off-screen), 3.5-11 s per page, and a warm-up home load.
- SHEIN risk control triggered after about 13 searches in one profile within about 10 minutes. The app must rate-limit
  hard (for example 1 search per 30 s or more, cache results) and treat `/risk/challenge` as BLOCKED (back off for hours).
- No login was needed and no login wall was seen. Cookies come from the anonymous browsing of the profile.
- Titles are English slugs, not true English titles. Category names and promo text are Arabic.
