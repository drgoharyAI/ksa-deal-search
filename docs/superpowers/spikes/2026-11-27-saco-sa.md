# Spike: saco-sa.search (www.saco.sa, English, SAR) - 2026-11-27

Status: PASS. Op `saco-sa.search`, AA site `saco-sa`, minTier 1 (plain HTTP, no browser, no cookies, no login).

## Data source
`www.saco.sa/en` is a Next.js (App Router, RSC) storefront in front of Adobe Commerce (Magento media on
`ops.saco.sa`). Search is Algolia (app `4AV7DL704C`, index `saco_eu_prod_en_products`, price-sorted replicas
`..._price_group_0_final_price_asc|desc`), queried **server-side**: `GET /en/products-search?q={q}` returns the
product grid as HTML, plus the raw Algolia hits in the RSC payload. The site's own search code runs two Algolia
requests per page, `is_in_stock_csaco:true` ("inStock") and `NOT is_in_stock_csaco:true` ("outOfStock"), and lists
the in-stock hits first. The client bundle also embeds a public search-only Algolia key; querying the index
directly with it was refused by this session's permission check, so the op reads the storefront's own page.

Search URL (spec): `https://www.saco.sa/en/products-search?q={q}&sortBy={sort}&sortDir={dir}`
- `sort`/`dir`: `custom-position`/`DESC` (Best match, the site default) or `price`/`ASC` (Lowest price); from the
  site's `sortKeys` (`price`/`DESC` and `special_price`/`DESC` also exist, unused).
- About 60 cards per page (`pageNo` exists, unused). A page is about 1.9 MB of HTML; a call takes about 2 s.

## Recipe (api-specs/saco-sa.json)
Learned with `capture` (two captures: air fryer, cordless drill) + `add --from <cap> --pick-request 1 --from2 ...
--html '<recipe>'`, then hand-edited to add the `sort`/`dir` slots (the captures had no sort params).
- items: `section:has(> div > a[href*="/product/"]):has(button.add-to-cart[data-id])` (a grid card; the featured
  card and the outer grid section do not match)
- id `button.add-to-cart@data-id` (18-digit SKU, leading zeros), title `button.add-to-cart@data-name` (English),
  price `button.add-to-cart@data-price`, currency `button.add-to-cart@data-currency` (`SAR` on every card),
  orig `p.line-through` (struck-out price, "1,399"), url `a[href*="/product/"]@href` (resolved absolute),
  image `img@src`, rating `.star-rating@style` (`--rating:N`, whole stars, 0 = none),
  stock `div.md\:hidden > span:last-child` (card badge), cart `button.add-to-cart > span` (button text).

## Field mapping to Product (src/sites/saco-sa/search.ts)
id = a numeric SKU without leading zeros, or a lettered SKU as it is ("S0000002030"); url must start
`https://www.saco.sa/en/product/` and end `-p-<SKU>` (lower-cased);
listPrice = finalPrice = price; origPrice when above price; currency SAR (a card naming another currency is dropped);
rating when 1..5; image when https. Availability (explicit signals only): badge "In stock" / "Limited stock" with
"Add to cart" -> `inStock: true`; the button "Click and pick" (badge "Out of stock" or none) -> `pickupOnly: true`
(kept and labelled: SACO cannot deliver it from the default region, a branch can hand it over); anything else, e.g.
"Out of stock" with no button or with "Add to cart", -> unknown.

## No-results page (fix round 1)
A search with no hits (one live check, `q=zxqvbnmplk`) returns 200 with an `h2` "No results found!" followed by
`p.text-gray.text-sm` "Try searching with different keywords...". The page also carries SACO's sign-in strings, and
API Anything checks for a login page before the recipe's `empty` selector, so an `empty` alone still answers `auth`.
The recipe therefore also matches that block as an item (`div:has(> h2 + p.text-gray.text-sm)`, field
`noResults: "h2"`): the answer is `ok` with one marker item, which the adapter's `isNoResults` names and the pipeline
skips, so the store answers ok with 0 products (no back-off, no "could not be read"). Fixture:
`tests/fixtures/saco-sa-empty.html`.

## Stock evidence (air fryer, 2026-11-27)
Algolia hits (RSC payload) against the rendered grid cards, 61 hits / 59 grid cards (one more hit is the separate featured card, one out-of-stock hit with qty 0 has no card):
| `is_in_stock_csaco` | mobile badge | desktop badge | button | cards |
|---|---|---|---|---|
| true | In stock / Limited stock | same | Add to cart | 31 |
| false | Out of stock | Limited stock | Click and pick | 28 |
`stock.is_in_stock` stayed true for 60 of 61 hits (the 61st, qty 0, had no card): it counts branch stock, so it is
not what the badge or the cart follows. The desktop badge says "Limited stock" on cards that cannot be delivered,
so the recipe reads the mobile badge, which matches `is_in_stock_csaco` on all 59 grid cards, and the normalizer also
requires the pickup-only button.

## Caveats
- HTML scrape of Tailwind class names (`md:hidden`, `line-through`); the button `data-*` attributes are the stable
  part. A redesign shows as `drift` (blocked status in the app).
- The connection to www.saco.sa was intermittently reset (TCP RST) for plain curl/Node requests during the spike,
  about 1 request in 3; retries succeeded. No API Anything call (about 20) failed.
- robots.txt disallows `/products-search` (and `/api/`) for crawlers and blocks AI crawlers by name. The app is a
  personal, user-initiated search at a low rate; keep it that way.
- Requests made: about 12 page loads (2 browser captures, 5 spike calls, 1 fixture, 1 favicon, a few curl probes)
  plus 16 for the eval recording.
