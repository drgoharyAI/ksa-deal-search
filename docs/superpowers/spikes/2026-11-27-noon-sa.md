### Data source and field mapping
The search page is server-rendered. The first render makes no client-side search or catalog JSON call; only cart, identity,
VIP and suggestions xhrs were seen. There is no `__NEXT_DATA__`. ld+json `ItemList` has only name and url.
So the data comes from the DOM: each `[data-qa="plp-product-box"]` card.
- `url`: card `a[href]`, made absolute, query string (`nav_ctx`, `o`) removed. It is always under `https://www.noon.com/saudi-en/`.
- `id`: the SKU from the URL, `/<SKU>/p/` (for example `N70131428V`).
- `title`: `[data-qa="plp-product-box-name"]@title`.
- `price`: `[data-qa="plp-product-box-price"] [class*=sellingPrice] [class*=amount]`. The currency glyph is an empty icon span.
- `origPrice`: `[class*=oldPrice]` (strike-through). It is null when the item has no discount. The `NN% Off` badge is next to it.
- `currency`: `"SAR"` from the page's OnlineStore ld+json (`shippingRate.currency`).
- `rating`: `[class*=textCtr]`. `reviews`: `[class*=countCtr] span`, for example "71.9K", which becomes 71900 (approximate).
- `image`: `img[class*=productImage]@src` (first slide, `?width=800`). It is null on a few cards.
Class names are hashed CSS-module names (`_amount_1bn4n_61`), so the prototype matches on `data-qa` and stable class substrings.
