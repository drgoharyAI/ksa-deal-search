# Spike: extra-sa.search (extra.com Saudi, English, SAR) - 2026-11-27

Status: PASS (Step 2 gate met). Op `extra-sa.search`, AA site `extra-sa`, minTier 1.

## Data source
extra.com/en-sa is SAP Commerce (Hybris) with search served by **Unbxd** (client-side). The page embeds a public
`unbxdSearchConfig` (apiKey `21705619e273429e5767eea44ccb1ad5`, siteKey `ss-unbxd-auk-extra-saudi-en-prod11541714990488`).
The op calls the Unbxd search API directly (not extra.com, so no Cloudflare on extra.com):
`GET https://search.unbxd.io/{apiKey}/{siteKey}/search?q={q}&rows=40&page={page}&sort={sort}&fields=...`
Search page: `https://www.extra.com/en-sa/search?text={q}` (`/search/?text=` 301-redirects to `/search?text=`).
The browser capture of that page did not record the Unbxd search XHR and the stored document is truncated, so the config
was read from a plain `curl` of the page and the Unbxd URL was captured directly (`capture <unbxd url>` then
`add --from <cap> --pick-request 1`). Server-side Hybris `/api/` was not needed.

## Recipe (spec: api-specs/extra-sa.json)
- params: `q` (required), `page` (optional, 1-based; Unbxd maps it to start=(page-1)*rows), `sort` (enum `score desc` (relevance) | `price asc` | `price desc`).
  Defaults live in the URL (`page=1`, `sort=score desc`); an empty sort value would be rejected. `relevancy desc` returns 400 - use `score desc`.
- `--extract response.products`; `fields=` in the URL limits the payload (full product is ~25 KB of city flags).
- `--pick`: `id=productCode, title, brand=brandEn, price, origPrice=wasPrice, discount, currency, rating, reviews=numberOfReviews, image=imageUrl[0], url=productUrl, inStock=inStockFlag, memberPrice=vipPrimePrice, status=productStatusEn`
- Spec was hand-edited after `add`: `page`/`sort` slots+params added, `volatile` emptied (AA flagged the key path segments), browser-document headers replaced.

## Field mapping to Product
id=id (productCode; marketplace items look like `MP00000527`, treat opaque); title=title (English); price=price (number, current sale price, SAR);
currency="SAR" (present in data, `currency` field); origPrice=origPrice (= wasPrice, list price; equals/absent when no discount; treat origPrice<=price as no discount);
discount=discount (percent, float, e.g. 24.14; present in data); rating (0 when none), reviews (0 when none); image=absolute https URL (media.extra.com);
**url = `url` field, already absolute** `https://www.extra.com/en-sa/<cat>/<slug>/p/<id>` (one product URL HEAD-checked: 200).
Extras: brand, inStock ("true"/"false" string), memberPrice, status (promo labels e.g. "White Friday Offer", "Last Piece Deal").

## Bait pricing / options
`price` is the normal sale price (price = wasPrice*(1-discount)). There are member/tier prices (Jood loyalty: `vipPrimePrice`, `basicPrimePrice`, Tamara/Tabby installment amounts) - these are lower than `price` but need membership; use `price` for comparisons, `memberPrice` only as info. No option-style bait pricing. Discounts are real list-vs-sale (22-35 of ~35 items discounted, esp. during White Friday). Offers have `endDateDiscount`. Marketplace sellers (id `MP...`) appear, same title repeated for variants (4 PROMATE earbud ids, same title) - dedupe by id AND title downstream. Results are accessory-heavy; app filter needed.

## Caveats
- Public Unbxd key could rotate; re-read `unbxdSearchConfig` from the search page.
- `rating`/`reviews` 0 means none. `inStock` is a string.
- Requests to extra.com: ~4 (1 browser capture page load, 2 curl page fetches incl. one redirect, 1 HEAD of a product page). Unbxd: ~30 calls.
